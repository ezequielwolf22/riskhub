v1.8.0 - Cambios Principales NUEVO

1. Auto-generacion de Riesgos al Crear Activo

Cuando usuario sube asset nuevo: POST /assets {name, asset_type, ...} ↓ Sistema crea Asset en BD ↓ Background task auto_generate_risks_for_asset() ├─ Query: SELECT * FROM Threat (amenazas org) ├─ Para cada threat: │ - Crear Risk [asset_id, threat_id] │ - Calcular inherent_level (ISO27005 5x5) │ - Aplicar controles existentes │ - Calcular residual_level │ - Comparar contra risk_appetite (USER DEFINED) │ └─ SI residual <= appetite: ACCEPTANCE automatica │ └─ SI residual > appetite: ASSESSED + email alerta └─ Ejecución paralela a analyze_asset_risks() IA

2. Auto-generacion de Riesgos desde CVE

Cada 24h cron _run_cve_auto_scan(): 1. Fetch NVD API (últimas 2 dias) 2. Para cada CVE encontrada: - Buscar activos afectados - auto_generate_risk_from_cve() - inherent_consequence=4 (CVE grave) - inherent_likelihood=3 (probable) - Calcular residual vs appetite - SI > appetite: email URGENT 3. Log: "CVE auto-scan: X CVEs, Y riesgos generados"

3. Auto-generacion desde OSINT

Cuando OSINT encuentra hallazgo CRITICAL/HIGH: auto_generate_risk_from_osint() ├─ Identificar asset afectado ├─ Crear threat "OSINT-TYPE" ├─ Risk [asset, threat] ├─ Calcular residual └─ SI > appetite: email alerta + mitigacion task

4. Risk Appetite Automatico

TODAS las creaciones de riesgo ahora comparan contra risk_appetite del usuario:

Condition Action
residual_level <= risk_appetite status=ACCEPTED (automatico)
residual_level > risk_appetite status=ASSESSED (user debe tratar)
Nota: risk_appetite viene de RiskContext.risk_appetite (configurable por org en UI)

Entrada del Usuario

Campo Tipo Requerido
name string Si

Flujo Completo: CVE Auto-Gen NUEVO

Trigger

Cron: Cada 24 horas | Funcion: _run_cve_auto_scan()

Logica

1. Query IntegrationConfig "nvd_cve" 2. IF not configured: return 3. Fetch NVD API (últimas 2 dias) - Filter: CRITICAL o HIGH - Max: 50 resultados 4. Para cada CVE encontrada: a) Search activos afectados - ilike description / name b) Para cada asset: - auto_generate_risk_from_cve( asset_id, cve_id, inherent_consequence=4, inherent_likelihood=3 ) c) Calcular residual d) Comparar vs appetite e) SI > appetite: email alerta 5. Log: "CVE auto-scan: X CVEs, Y riesgos"
Parametros: inherent_consequence=4 (CVE grave), inherent_likelihood=3 (probable)

Risk Appetite - AUTO-ACCEPTANCE

Configuracion por Org

Campo Valor Rango
risk_appetite User defines 0-8
risk_matrix ISO27005 default 5x5

Logica de Auto-Acceptance

En ANY creacion de riesgo: 1. GET RiskContext.risk_appetite (ej: 3) 2. Calcular residual_level - Aplicar controles existentes - Usar matriz risk 3. IF residual_level <= appetite: risk.treatment_option = ACCEPTANCE risk.status = ACCEPTED → SIN email, SIN requerimiento manual 4. ELSE: risk.status = ASSESSED → User debe elegir tratamiento → Email alerta si HIGH/CRITICAL

Ejemplo

Risk inherent Controles residual appetite Resultado
RSK-001 4 Reduccion 50% 2 3 ACCEPTED auto
RSK-002 5 Reduccion 20% 4 3 ASSESSED + email

Security Review - v1.8.0

Multi-Tenancy ✓

- Todos los queries filtran por organization_id - auto_generate_risks_for_asset valida org_id - CVE auto-gen solo afecta activos de la org - NO data leakage cross-org - Risk creados heredan org_id del asset

Injection Prevention ✓

- No hay inputs directos de usuario - Todo viene de BD (types enumerados) - SQLAlchemy ORM (no raw SQL) - Logging escapa valores

Race Conditions ✓

- Duplicado prevention: query [asset_id, threat_id] - Transacciones con commit/rollback - Background tasks thread-safe (SessionLocal)

Audit Trail ✓

- Risk.created_at = now() - Logger.info/warning detallados - AuditLog puede ampliarse
Conclusión: v1.8.0 mantiene estándares security existentes. No nuevas vulns introducidas.
